## 決定事項
- `aws-cost-analyst` は廃止し、コスト分析は AWS 公式の `aws-core@agent-toolkit-for-aws` に一本化する
- `aws-pricing-mcp-server` を個人設定に残す選択肢は採らず、プラグインごと削除する（→「捨てた選択肢」参照）
- コミットは2本に分割する。1本目がプラグイン削除、2本目が CLAUDE.md の整理
- コミットメッセージに `Co-Authored-By` / `Claude-Session` トレーラを付けない。PR 本文にもセッション URL 行を入れない。直近の同種コミット `3218e28` も `Refs #31` で終わっており、既存の運用と一致する
- リリース本文は CHANGELOG の該当バージョンのセクションをそのまま使う（v0.0.10 以前と同じ形式）
- 廃止したプラグインのキャッシュは手動で削除する（自動 GC を待たない）

## 捨てた選択肢と理由
- `aws-pricing-mcp-server` だけ個人設定（`~/.claude/settings.json` または `.mcp.json`）に残す案: `analyze_terraform_project` を維持する目的だったが、Claude Code 本体の Read/Grep で .tf を読み `call_aws` で価格を引けば代替できると判断 — プラグインごと完全削除を採用
- CLAUDE.md の未コミット変更を別 PR に分ける案: 削除対象のテーブルに `aws-cost-analyst` 行が含まれており、分けると後続 PR でコンフリクトが発生する — 同じ PR の2コミット目として取り込む方式をユーザーが選択
- CLAUDE.md の未コミット変更を破棄する案: テーブルとディレクトリ構造規約を残す選択肢だったが、marketplace.json と README の重複であり毎回陳腐化するため不採用
- README に uvx 前提を残す案: 残存 MCP が remote HTTP の `aws-knowledge-mcp-server` のみになり uvx も AWS_PROFILE も不要になるため削除

## 学び
- マーケットプレイスからプラグインエントリを削除しても、インストール済み環境からは消えない。`~/.claude/settings.json` の有効化フラグ、`installed_plugins.json` のエントリ、`cache/` の実体が残り MCP サーバーも起動し続ける。`/plugin uninstall <plugin>@<marketplace>` が別途必要
- `aws-core@agent-toolkit-for-aws` の MCP は marketplace.json の `mcpServers` フィールドではなくプラグインディレクトリ直下の `.mcp.json` で定義されている。marketplace.json だけを見ると MCP なしに見えるため誤判定しやすい
- `agent-toolkit-for-aws` の GitHub org は `awslabs` ではなく `aws`。ディレクトリ名から推測せず `~/.claude/plugins/known_marketplaces.json` を見る
- プラグインキャッシュには GC 機構がある。`.orphaned_at` に孤立時刻の Unix ミリ秒、`.in_use/<pid>` に `{"pid":..,"procStart":".."}` 形式のリースが置かれ、現役バージョンには `.orphaned_at` が付かない。ただし孤立マークから14日経過しても削除されない実績があり、保持期間は不明。廃止時は手動削除が確実
- `aws-billing-and-cost-management` skill は数値計算を LLM にさせず `run_script` に委ねるルールを明文化している。自前エージェントには無かった品質保証で、置き換えの根拠として有効だった
- `aws-mcp` の `call_aws` はローカルファイルにアクセスできない。`analyze_terraform_project` のようなファイル入力型ツールの代替にはならず、Claude Code 本体の Read/Grep と組み合わせる必要がある
